# Session Board：功能、验证与开发记录

这是看板唯一的说明文件，记录全部功能、每项怎么验证、开发进度和历史，以及踩过的坑。改看板时只更新这一个文件。

当前版本 **0.21.1** · 最近一次全量核对 2026-10-26

---

## 1. 开发流程（每个新功能都必须按顺序走完）

1. **先登记**：在第 4 节功能表里加一行，状态先填 ⏳，**同时写清三种验证方法**：自动测试测什么、线上用什么数据核对、人工要点哪里看什么。写不出验证方法的功能不开工。
2. **先写测试**：按第 1 步写的验证方法，在 `tests/board.test.ts` 里加用例。需要真实接口格式的，先抓一份真实返回放进 `tests/fixtures.ts`。
3. **实现**。
4. **跑 `./check.sh`**：静态校验加全部测试必须全过，旧用例一条不删。
5. **反向对照**：把新逻辑临时去掉或改坏，确认新用例确实会失败。这一步就是为了防止"测试没测到点上"。
6. **更新本文件**：功能表里的状态和日期、第 5 节版本历史；如果踩了新坑，记进第 6 节。
7. **提交并发布**：`git commit` → 提高版本号 → 把文件同步到 `raymondhe0/useful-skill` 的 `plugins/session-board/` 并推送 → `claude plugin marketplace update useful-skill` → `claude plugin update session-board@useful-skill` → 新会话里用 `board_debug` 核对 `version`。
8. **线上核对**：按第 1 步写的线上方法查一遍，再把结果和日期填回功能表。只有人工能验证的项留 ⏳，并告诉用户要点哪里。

任何一步失败就先修，不在失败的基础上叠加新功能。

## 2. 怎么用

- **打开**：新会话会自动打开；手动打开就在输入框输入 `/board`。
- **顶部**：额度（5 小时 / 每周）、上次更新时间、**Refresh**、**?**（栏目说明）、筛选框。
- **四个栏目**：Running（蓝，正在工作）· Needs me（橙，见 #9 的规则）· Finished (24h)（绿，24 小时内有活动）· Idle（灰，更早的或手动挪过去的，每个会话一行）。
- **卡片**（全部展开）：
  - 标题行：标题 + 模型、强度下拉框
  - 信息行：目录 · 多久前 · 上下文 % · Open / Reply / Stop / Move to Idle（靠右）
  - Needs me 原因 + Dismiss
  - Task
  - Progress（括号里是这段文字出现了多久）
  - 发消息框（点 Reply 展开；Needs me 默认展开）
  - 子会话（嵌在卡片底部）
- **作用范围**：Move to Idle、Dismiss 只是看板内的归类，所有会话间同步，会话有新活动后自动失效；Stop、改模型、改强度、发消息会作用到真实会话。
- **配置**（config 菜单 → session-board）：
  - Open the board at session start：默认开
  - Refresh interval (seconds)：默认 3，范围 1–60

| L4c 跨会话 | 在一个会话里操作，在另一个会话里用 `board_debug` 看结果；或者直接读共享存储文件 | Claude / 用户 | 两边一致 |
| L5 人工 | 看界面、真实点击 | 用户 | 按功能表里的人工一栏逐项确认 |

- **盲区**：`claude plugin test` 只在测试失败时才打印引擎警告，"元素被降级渲染"这类问题在通过的测试里看不到（v0.1 的 `claude://` 链接就是这样漏掉的）。对策是直接检查渲染树，并做反向对照（流程第 5 步）。
- **安全约束**：会改动真实会话的操作（停止、发消息、改模型），Claude 只在测试里用假数据验证；线上自检只读；真实点击留给用户。
- **探测的副作用**：给某个会话发消息会让它产生新活动，于是它对 Move to Idle 和 Dismiss 的归类会自动失效。线上核对时尽量用只读方式。

### 已知限制

- **Needs me 很少触发。** 这个 app 里，会话把提问放在底部的"下一步"框，这部分不写进转录，看板读不到；以陈述句结尾的"等你审 diff"也不算。实际上几乎每个 Finished 会话都在等你。候选方案是合并成 "Waiting for you"，再用已读/未读区分，还没定。
- **其他会话的上下文 % 只有桌面端有。** VS Code 和终端只能看到自己的。
- **Stop、改模型、改强度只有桌面端能做，且只对桌面会话。** 引擎没有提供跨会话的同类接口。
- **Windows 没测过。** 进程存活判断和读记录尾部用的是 `/bin/ps`、`/usr/bin/tail`。
- **子会话和子代理是两种东西。** 子会话是用开新会话方式派生的完整会话（侧边栏可见，能直接对话、改模型、停止），在会话列表里带 `startedBy`，显示为完整卡片（#14a）。子代理是会话内部用 Agent 工具派出的帮手，不在会话列表里，结果交回母会话；看板只显示它的状态和进展（#14b），要调整它就和母会话说。

## 6. 坑与经验

- **发布**：只改文件夹里的版本号，各会话不会更新，必须执行 `claude plugin update session-board@useful-skill`。之后用 `board_debug` 的 `version` 确认每个会话实际在跑的版本。
- **热加载**：由别的会话回报或自动事件触发的回合里改的文件，回合结束时不会热加载；`touch` 不改内容也不会触发。实在不行就让用户在输入框输入 `/reload-plugins`。
- **CLI 路径**：`claude` 不在 PATH 里，而且路径随 app 版本变化。脚本里一律这样找：`ls -d ~/Library/Application\ Support/Claude/claude-code/*/*/claude.app/Contents/MacOS/claude | sort -V | tail -1`。
- **共享存储**：文件是 `~/.claude/plugins/store/session-board_useful-skill-*.json`，里面有 lease、board、shelved、dismissed，排查同步问题时直接读它。存储按插件安装身份分文件，换了安装方式就是另一份存储。
- **自己的 id**：用 `get_session('self')` 取。`$.session.id()` 返回的是转录文件名，不等于 `local_…` 会话 id。
- **`$.state`**：跨热加载保留；只能存 JSON，写入时不能带值为 undefined 的字段；给缓存加新字段时，要考虑旧缓存怎么升级。
- **渲染**：`Text` 不认 `key`，需要定位的文字要包在带 key 的 `Box` 里；`find({ text })` 是子串匹配、最外层优先，查标题要精确比对；桌面端只把 `https:` 链接渲染成可点击。
- **接口**：`send_message` 返回 isError 不等于没送到，要看 `delivery` 字段；`list_events` 不接受 self；会话启动的那一刻 `ui.open` 会返回"未放置"。
- **测试工具**：事件钩子的底部实现直接返回结果（如 `{ cwd }`），`$` 调用要返回 `{ value }`；测试里不允许动态 `import()`。
- **子代理的数据来源**：子代理不在会话列表里，只有它所属会话的插件能通过 `$.agent.list()` 看到，所以必须由每个会话自己上报；母会话的看板没在跑就没有上报。
- **本地文件**：`~/.claude/sessions/*.json` 只列活着的会话，崩溃会留下旧文件，要用 `ps` 再滤一次；`hostSessionId` 只有桌面会话有，是对上 `local_…` id 的唯一依据；`.key` 文件不要读。`$.fs.read` 超过 4 MiB 会拒绝，所以记录用 `tail`/`head` 读。`session.send` 的测试桩要直接返回 `{ isDelivered }`，不包 `value`。
- **看界面**：Claude 截不到真实面板（`screencapture` 被拒，内置浏览器面板隐藏时打不开本地地址）。用 `tools/ui-preview/run.sh`：取引擎画出的真实渲染树，转成网页再截图。布局和文字可信，颜色和按钮样式是照用户截图模仿的，最终以用户截图为准。桌面和 VS Code 把所有按钮画成实心按钮，`plain` 无效。
- **验证**：只在自己的会话里验证不够，"新会话"和"其他会话"的情况要用新会话探针或跨会话核对。
